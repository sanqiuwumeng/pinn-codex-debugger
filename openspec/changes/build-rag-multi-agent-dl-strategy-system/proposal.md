## Why

当前 `pinn-hybrid-rag` 已经能够以确定性方式完成 PINN 症状路由和手册证据检索，但它仍然是只读的检索产品，不能覆盖 PINN 实验从需求确认、物理模型审计、方案决策、受控执行、过程监督、指标校验到知识沉淀的完整生命周期。目标系统面向不同 PDE、几何、边界条件、输出通道和参考证据的普适 PINN 策略优化，不把任何单一传热案例提升为系统默认物理模型。

如果直接在现有 MCP 服务上叠加多个自由对话 Agent，系统会面临指标偏好被擅自假设、单位和量纲错误未被发现、平均误差掩盖局部严重错误、实验状态不可恢复、训练动作缺少审批、以及未经验证的结论污染 Wiki 和技能库等风险。因此需要先定义一个具有“执行层—编排层—保障层”物理隔离、显式状态、确定性验证和人工审批边界的正式架构。

## What Changes

- 新增基于 LangGraph 的显式实验状态机，由编排层负责路由、候选方案生成、决策、预算和审批协调，不采用无约束的群聊式 Agent 架构。
- 新增执行层专业组件，覆盖项目检查、RAG 检索、实验方案生成、训练执行、事件监控、预测场分析、指标计算以及 Wiki/Skill 候选生成。
- 新增保障层硬门禁，覆盖实验完整性、物理参数单位与量纲、无量纲化链式缩放、指标优先级、可复现性、成本风险、产物完整性和人工审批。
- 新增“普适核心—领域插件—案例契约”三级功能边界：核心只定义通用契约和确定性算法，领域插件提供可选物理指标与上下文，案例契约记录用户模型、单位体系、参考证据、ROI、时窗和阈值。
- 将用户提供的 PDE、BC、IC、几何和参数定义为 `PhysicalModelAuthority`；将解析解、实验、高保真数值解或教师数据定义为独立 `ReferenceEvidence`，禁止把某种数值方法设为全局默认真值。
- 单位审计以用户模型声明的内部单位体系为目标，允许 SI、CGS、mm-based 或其他自洽体系；真正阻断实验的是未声明混用、遗漏转换、重复转换和方程量纲不一致，而不是“非 SI”。
- 要求优化决策前主动向用户确认参考真值、主指标、守护指标、诊断指标、关注区域和可接受退化；未确认时不得自动设置指标权重。
- 要求分析预测误差的时空位置，包括 `max_abs` 的 `argmax`、top-k 极值点、高误差连通区域、时间轨迹、局部 PDE residual、采样密度和物理区域，而不是只读取 MSE/RMSE。
- 在保留现有确定性检索器和来源追踪能力的前提下，引入带元数据过滤、稀疏/稠密融合和可重建索引的向量数据库 RAG。
- 建立实验系统记录、追加式审计事件、实验 Wiki 和可复用 Skill 候选的持久化边界；未经验证的 Agent 输出不得进入正式知识库。
- 默认仅允许自动执行只读检查和获批的 smoke；修改现有代码、安装依赖、完整训练、发布模型和提升 Skill 均需要明确审批。

## Capabilities

### New Capabilities

- `three-layer-agent-orchestration`: 定义执行层、编排层和保障层的隔离边界、LangGraph 状态机、显式数据契约、持久化和人工中断语义。
- `physical-parameter-audit`: 定义实验前的参数来源追踪、单位标准化、PDE/BC/IC 量纲检查、无量纲化导数缩放检查和歧义确认流程。
- `metric-priority-and-error-localization`: 定义用户指标优先级确认、分层指标契约、预测场时空误差定位以及进入优化决策的证据门槛。
- `experiment-lifecycle-governance`: 定义实验完整性审计、单逻辑改动、smoke-first、事件驱动监督、指标复核、回滚和完整训练审批流程。
- `rag-knowledge-persistence`: 定义确定性检索与向量检索融合、来源可追踪索引、实验记录、Wiki 版本化和 Skill 候选晋级流程。

### Modified Capabilities

- None. 当前 `pinn-hybrid-rag` 运行时在本 change 的规划阶段保持不变；后续实现通过适配器复用，而不是在提案阶段修改。

## Impact

- 目标工作树：仅 `exp/hybrid-rag`；不得创建新 worktree，也不得修改 `exp/rules-mcp`、`exp/skill-only` 或外部 `skill_test`。
- 运行时实现必须遵循本 change 的审批记录和阶段门禁；传热测试资产只能作为验证案例和可选领域插件，不能成为通用核心的隐式依赖。
- 未来可能涉及 LangGraph、持久化 checkpointer、实验跟踪、对象存储和向量数据库；具体包、版本、模型和部署方式必须在实现前形成依赖计划并获批。
- 当前手册、现有 MCP 工具、已恢复测试和历史实验产物必须保持不变；所有现有文件在未来修改前必须按 `original_filename_backup_YYYY-MM-DD` 规则备份。
- 数据安全：不得自动删除或覆盖实验数据；向量数据库必须被视为可重建索引，而不是事实来源。
- 审批边界：本提案只授权架构规划。开始任何架构实现前，用户仍需针对本 change 明确回复 `Yes`，并确认环境与依赖方案。
